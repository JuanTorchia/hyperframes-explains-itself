# Thesis

## Project Thesis

Use HyperFrames to explain HyperFrames.

The project should demonstrate HyperFrames through a real build process, not through abstract claims. The final video matters, but the build trail matters just as much.

## Why This Is Worth Doing

Many developer tools are introduced with polished demos that skip the friction. That can make the tool look impressive while leaving developers unsure how to start, what can fail, or what a realistic workflow feels like.

This project takes the opposite approach:

- Start with a small, concrete video.
- Document the setup.
- Keep the script and storyboard visible.
- Record the commands.
- Log mistakes.
- Render only after the source is clear.

## Claim To Test

HyperFrames should make it practical to treat HTML as the source for video and MP4 as the generated artifact.

That claim is only useful if the workflow can be reproduced by another developer.

## Non-Goals

- This is not a full HyperFrames course.
- This is not a marketing landing page.
- This is not a benchmark.
- This is not a claim that HyperFrames is the best tool for every video workflow.

## Definition Of Done

This project is done when:

- The repository documents the full workflow.
- The video source can be inspected.
- The preview path is documented.
- The render path is documented.
- The final MP4 is produced.
- The journal includes real notes about issues encountered during the build.
